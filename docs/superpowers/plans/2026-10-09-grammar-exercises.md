# Grammar Exercises Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shared practice screen at `/topics/<slug>/practice` plus 30 checked exercises for every catalogue topic (except noun-gender, which keeps `/articles`), with logged-in answers saved to `attempts` so progress, "Your focus now" and topic pages show them.

**Architecture:** Exercise content is static JSON per topic in `lib/exercises/data/<slug>.json`, validated by a Node test. A sync script generates `lib/exercises/sets.ts` (static imports, so Vercel bundles them) and adds the practice link to `lib/grammar/topics.json`. Pure checking/round logic lives in `lib/exercises/check.ts`. A server action re-checks answers and inserts into `attempts`. A client component runs rounds of 10.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind 4, Supabase, `node:test`, playwright-cli.

**Spec:** `docs/superpowers/specs/2026-10-09-grammar-exercises-design.md`

## Global Constraints

- No new npm packages. No AI calls at runtime.
- 30 items per topic; rounds of 10; English instructions/explanations; German sentences at the topic's level.
- Item types exactly: `choice`, `type`, `order` (shape in Task 1).
- Typed answers: trim + collapse whitespace, case-sensitive, any of `answers`. Order: tokens joined by single spaces must equal one of `answers`.
- Attempts insert: `topic` = slug (≤ 32), `item_id` ≤ 64, `answer` clipped to 64 chars; correctness computed on the server.
- noun-gender is excluded (its exercise is `/articles`).
- Visual language: existing tokens (`--paper`, `--accent`, `--line`), 8px accent shadow cards, pill buttons; phone width without horizontal scroll; keyboard playable (Enter submits/continues); `role="status"` for feedback.
- Branch `feature/grammar-exercises`; commit per task; no merge/push.

## Review Focus

1. A typed answer with an extra space or a trailing full stop is wrongly marked wrong → normalisation tests in Task 1 (`"  dem  "` correct; trailing punctuation NOT stripped, so prompts never put punctuation inside the gap).
2. A choice item whose correct answer isn't among its options, or duplicate options → validation test in Task 1 over every data file.
3. Word-order items whose tiles can't form the accepted answer → validation test (multiset of tokens equals each answer's tokens).
4. A forged `itemId`/`slug` sent to the server action → ignored, nothing inserted (Task 2 code + review).
5. A topic with exercises but no link on its topic page, or a link to a missing set → sync consistency test (Task 1).

**Interfaces (Produces):**

```ts
// lib/exercises/types.ts — no imports
export type ChoiceItem = { id: string; type: "choice"; prompt: string; options: string[]; answer: string; explanation: string };
export type TypeItem = { id: string; type: "type"; prompt: string; hint?: string; answers: string[]; explanation: string };
export type OrderItem = { id: string; type: "order"; words: string[]; answers: string[]; translation?: string; explanation: string };
export type ExerciseItem = ChoiceItem | TypeItem | OrderItem;
export type ExerciseSet = { slug: string; instructions: string; items: ExerciseItem[] };
```
- `prompt` (choice/type) contains exactly one `___` marking the gap; never put punctuation inside the gap. `hint` e.g. `"(gehen)"`.
- `words` for order = the sentence's tokens (punctuation attached to its word), stored in correct order; the UI shuffles.

```ts
// lib/exercises/check.ts — imports only types
export const ROUND_SIZE = 10;
export function normalise(s: string): string;            // trim, collapse internal whitespace to one space
export function isCorrect(item: ExerciseItem, answer: string): boolean;
// choice: answer === item.answer; type: normalise(answer) in item.answers.map(normalise); order: normalise(answer) in answers.map(normalise)
export function correctAnswer(item: ExerciseItem): string; // choice.answer | answers[0]
export function shuffle<T>(xs: T[], rand?: () => number): T[]; // Fisher–Yates, copy
export function makeRound(items: ExerciseItem[], size = ROUND_SIZE, rand?: () => number): ExerciseItem[]; // random distinct `size` items (or all if fewer)
```

**Validation test `lib/exercises/data.test.mjs`** (reads every `lib/exercises/data/*.json` with `readdirSync` and `JSON.parse`, and `lib/grammar/topics.json`). For each set:
- `slug` equals file name, exists in the catalogue, is not `noun-gender`; `instructions` non-empty English.
- exactly 30 items; ids unique within the set, `^[a-z0-9-]{1,64}$`.
- every item has `explanation` 10–300 chars.
- choice: 2–4 options, unique, `answer` ∈ options, prompt contains `___` exactly once.
- type: prompt contains `___` exactly once, `answers` non-empty, each ≤ 64 chars, no answer contains `___`.
- order: ≥ 3 words; for each answer, `answer.split(" ")` sorted equals `words` sorted; `words.join(" ")` ∈ answers.
- consistency: every data slug has topics.json `exercises[0].href === "/topics/<slug>/practice"`; every topic whose href matches `/topics/*/practice` has a data file; `lib/exercises/sets.ts` mentions every data slug.
With no data files yet, the per-set checks simply loop zero times (test still passes).

**Unit tests `lib/exercises/check.test.mjs`:** normalise (`"  dem  Bus "` → `"dem Bus"`); isCorrect for each type including case sensitivity (`"Dem"` ≠ `"dem"`), multiple accepted answers, order with alternatives; correctAnswer; makeRound returns 10 distinct items from 30, all items if fewer than 10, deterministic with a seeded `rand`.

### Task 2: Saving answers and per-topic progress for all topics

**Files:** Create `app/topics/[slug]/practice/actions.ts`. Modify `lib/learning/progress.ts` (+ its test in `lib/learning/focus.test.mjs`), `lib/attempts.ts`.

- `progress.ts`: replace the fixed map with `slugForAttemptTopic(topic: string): string` — `"articles"` → `"noun-gender"`, otherwise the topic itself. `topicProgress` uses it. Keep `ATTEMPT_TOPIC_SLUG` only if still referenced (grep); otherwise remove. Test: rows with topic `"dative-case"` count under `dative-case`; `"articles"` still maps to `noun-gender`.
- `actions.ts`:
```ts
"use server";
import { EXERCISE_SETS } from "@/lib/exercises/sets";
import { isCorrect } from "@/lib/exercises/check";
import { createClient } from "@/lib/supabase/server";

/** Saves one exercise answer for the logged-in user; correctness decided here. Guests: no-op. */
export async function recordExerciseAnswer(slug: unknown, itemId: unknown, answer: unknown): Promise<void> {
  if (typeof slug !== "string" || typeof itemId !== "string" || typeof answer !== "string") return;
  const item = EXERCISE_SETS[slug]?.items.find((i) => i.id === itemId);
  if (!item || answer.length > 500) return;
  const supabase = await createClient();
  const { data } = await supabase.auth.getClaims();
  if (!data?.claims) return;
  const { error } = await supabase.from("attempts").insert({
    topic: slug, item_id: itemId, answer: answer.slice(0, 64) || "-", correct: isCorrect(item, answer),
  });
  if (error) console.error("recordExerciseAnswer failed:", error.message);
}
```
  (`Object.hasOwn(EXERCISE_SETS, slug)` instead of `?.` to avoid prototype keys like `__proto__`.)
- `lib/attempts.ts`: add `getTopicAccuracy(slug: string): Promise<{ total: number; correct: number } | null>` (null for guests; pages with `range` like `getAttempts`, selecting `correct` only, filtered by topic). Reuse the private pager rather than duplicating it.

### Task 3: The practice page

**Files:** Create `app/topics/[slug]/practice/page.tsx`, `components/exercises/ExerciseSession.tsx` (client; may split item views into `components/exercises/ChoiceItem.tsx`, `TypeItem.tsx`, `OrderItem.tsx` if it grows past ~250 lines). **page.tsx (server):** `generateStaticParams` → `Object.keys(EXERCISE_SETS)`; `dynamicParams = false`; `generateMetadata` → `"<topic title> — Practice"`; unknown → `notFound()`. Renders breadcrumb (Grammar Topics › level › topic › Practice), title, `set.instructions`, and `<ExerciseSession slug items loggedIn />`. `loggedIn` from `getClaims()`.

**ExerciseSession (client):**
- State: round items (`makeRound`), index, answered (answer, correct), round results, mode (`"normal" | "mistakes"`).
- choice: options as buttons (shuffled once per item); click = answer.
- type: prompt with an inline `<input>` in the gap (label = the sentence; `autoComplete="off"`, `spellCheck={false}`, `lang="de"`), hint shown after the gap, Enter or "Check" submits; empty input can't submit.
- order: shuffled word tiles; click a tile to append it to the answer line, click a placed tile to put it back; "Check" when all tiles placed; "Clear".
- After answering: green/red feedback (`role="status"`), the correct answer, the explanation; a "Continue" button that receives focus (Enter continues). Call `recordExerciseAnswer(slug, item.id, answer)` fire-and-forget when `loggedIn`.
- Progress line: "Question 3 of 10 · 2 correct".
- Round end: "You got 7 of 10", buttons "Practise my mistakes (3)" (only if misses; replays exactly those items), "Next 10" (new `makeRound`), link "Back to <topic>". Guests see "Log in to save your progress" link (`/login?next=/topics/<slug>/practice`).
- German text gets `lang="de"`.
